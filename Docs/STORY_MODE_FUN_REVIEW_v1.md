# 스토리모드 재미요소 검토 v1 — 다른 육성게임과 비교 (2026-09-17, 104차)

> 성격: **검토·제안 문서. 코드·대본·엔딩 구성은 아무것도 바꾸지 않았다.** 아래 제안 중 이야기·단서·엔딩 조건에 닿는 것은 「결정 필요」로 따로 표시했다 — 사용자 허락 전에는 손대지 않는다.
> 기준 코드: `Raising/TamaRaisingUI.cs`, `Meta/{Survival,StoryProgress,StoryGate,LevelSystem,Timeline,ScheduleTable,RandomEventTable,StoryContest}.cs`, `Story/{ClueSystem,StoryEventBeat}.cs`
> 레퍼런스: 우마무스메(육성 모드), 프린세스 메이커 2, Long Live the Queen, 다마고치, 스타듀 밸리

---

## 0. 결론 한 줄

**키운 결과가 아무 데도 안 쓰인다.** 체력 게이트는 설계부터 「자동으로 대충 키워도 통과」 기준이고, 대회는 이야기와 따로 놀고, 단서·엔딩은 카드 버튼으로 정해진다. 그래서 행동 3칸을 무엇으로 채우든 결과가 비슷하고, 「자동」을 켜 둬도 끝까지 간다. 다른 육성게임은 모두 **「이번 주 선택 → 곧 닥칠 시험 → 결과가 이야기를 바꾼다」**가 한 줄로 이어져 있다. 이 연결을 만드는 것이 1순위다.

## 2. 왜 재미가 없나 — 진단 7개

**① 선택이 결과를 바꾸지 않는다 (가장 큼)**
- 스탯이 쓰이는 곳은 체력 게이트 하나뿐인데, 게이트는 원래 설계부터 「자동이 대충 굴러도 통과, 여유 5배」다(`RAISING_TAMAGOTCHI_v3` §2). 밥 행동(체력 +1)과 레벨업(체력 +2)이 따로 체력을 계속 올려 준다. 실제 플레이에서 게이트에 막히는 빈도는 아직 재지 않았다 — 확인 필요.
- 순발력·매력은 러닝에 실제로 들어가지만(`RunTuning`: 순발력 100 → 레인 이동 38% 빠름 등) **화면 어디에도 그 사실이 안 보인다.** 감성은 쓰이는 곳이 거의 없다.
- 단서 6개는 컷씬 뒤 카드에서 버튼으로 얻는다. 육성과 상관이 없다.
- → 프린세스 메이커는 스탯 조합이 **74개 엔딩**을 가르고, Long Live the Queen은 이벤트마다 **스킬 체크**로 생사가 갈린다. 우리는 키운 것이 어디에도 부딪히지 않는다.

**② 가까운 목표가 안 보인다**
- 대회와 대회 사이가 6~9주(18~27번 누름)인데, 그동안 「무엇을 향해 키우는지」가 화면에 없다. 게이트 숫자는 체력바의 눈금뿐이다.
- → 우마무스메는 **「○월까지 이 레이스에서 몇 등 안에 — 못 하면 육성 끝」** 목표가 늘 화면에 있고, 매 턴 그 목표에서 거꾸로 계산하게 만든다.

**③ 행동을 누르기 전에 결과를 모른다 → 고민이 없다**
- 카드에는 이름만 있고, 얻는 스탯·실패 확률이 없다. 결과는 누른 뒤 말풍선 한 줄로만 나온다.
- → 우마무스메는 훈련 버튼마다 **오를 수치와 실패율(%)**을 먼저 보여 준다. 「실패율 18%인데 지금 무리할까, 쉴까」가 곧 게임이다.

**④ 행동끼리 엮이지 않는다**
- 같은 알바를 계속해도, 놀기와 교육을 섞어도 특별한 일이 없다. 카드 2장도 매번 무작위라 계획을 세울 수가 없다.
- → 우마무스메: 같은 훈련을 반복하면 **시설 레벨**이 오르고, 친한 서포트 카드가 같은 칸에 모이면 **우정 훈련**이 터진다. 프린세스 메이커: 알바를 계속하면 숙련도가 붙는다.

**⑤ 생활 관리가 벌만 있고 상이 없다**
- 장보기 → 조리 → 밥 → 잠 → 옷은 안 하면 깎이기만 한다(74차에 「공짜 회복」도 없앴다). 잘 챙겨도 「본전」이다.
- → 다마고치는 돌봄을 잘한 정도가 **어떤 어른으로 자랄지**를 바꾼다. 돌봄이 곧 결과다.

**⑥ 사람이 없다**
- v3 간소화 때 호감도·친밀도를 지웠고, 인물은 컷씬 안에만 있다. 육성 화면에서 만나는 사람은 꼬마 말풍선뿐이다.
- 이야기의 핵심 인물(꼬마·아줌마·매일 마주치는 사람)이 육성 중에는 보이지 않으니, CS7의 반전이 「내가 쌓은 시간」으로 느껴지기 어렵다.
- → 스타듀 밸리는 선물·대화로 **하트**를 쌓으면 인물마다 **하트 이벤트**가 열린다. 우마무스메의 서포트 카드도 친밀도 → 연속 이벤트다.

**⑦ 반응이 약하다**
- 대성공도 말풍선 + 하트 3개. 스탯이 올라가는 순간, 새 칭호, 새 카드 해금이 눈에 띄지 않는다.
- 미니게임은 순서가 정해져 있고 스탯과 무관하다.

## 4. 개선안

### P0 — 작게, 기존 코드 재사용 (대본·엔딩 안 건드림)

**P0-1. 카드에 「미리보기」 붙이기** (진단 ③)
- 카드 아래 한 줄: `체력 +3 · 순발력 +2 · 기운 −15 · 실패 12%`. 실패율은 지금 판정 공식(`ScheduleJudge`)에서 스트레스 단계·컨디션을 넣어 계산한 값을 그대로 보여 준다.
- 실패율 30% 이상이면 카드 테두리 빨강. 「쉬어야 하나?」가 생긴다.
- 손대는 곳: `TamaRaisingUI.CardPickRoutine`, `EventCardKit.ThemedPickCard`(글 한 줄 추가).

**P0-2. 「다음 대회까지」 목표 띠** (진단 ②)
- 육성 화면 위에 늘 한 줄: `CH4 대회 「사진 2장」까지 3주 · 추천 순발력 40 (지금 32)`.
- 대회 종류마다 **추천 스탯을 다르게**: 코인 대회 → 순발력, 사진 대회 → 매력, 보스 대회 → 체력, 완주 → 체력+순발력. 지금 러닝이 스탯을 이미 반영하므로(`RunTuning.Configure`) 「추천」은 실제로 러닝을 쉽게 만드는 값으로 정한다.
- 대회 안내 카드(`ContestIntroUI`)에 「순발력 덕분에 레인 이동 12% 빨라요」처럼(값은 `RunTuning` 에서 그대로) **내가 키운 것이 어디에 쓰였는지** 한 줄.

**P0-3. 같은 행동 반복 = 숙련** (진단 ④)
- 카드별 숙련 Lv 1~5(그 카드를 한 횟수). Lv이 오를수록 수치 +10%씩, 알바는 수입 +10%씩. 카드에 ★로 표시.
- 카드 2장 중 **1장은 지난주에 한 카드**가 나오도록(나머지 1장은 무작위) → 계획을 이어 갈 수 있다.

**P0-4. 생활 관리에 「상」 붙이기** (진단 ⑤)
- 4주 연속 잘 먹고 잘 잔 주 → 결산 카드에 「좋은 한 달」 도장 + 다음 주 성장 +20%.
- 결산 카드 순서를 **이번 주에 오른 것 먼저, 깎인 것 뒤**로.
- 장보기 귀찮음: 마이룸에 「정기 장보기」 토글(매주 쌀·반찬 자동 구입, 돈 있을 때만).

**P0-5. 성장 순간 연출** (진단 ⑦)
- 스탯이 10단위를 넘을 때 짧은 팡 + 말풍선(「이제 오름 정상까지 안 쉬고 가!」).
- 새 카드 해금(`LockReason` 이 풀린 순간)에 토스트 「새 알바: 등대 지킴이」.

**P0-6. 자동 모드는 「효율 낮음」으로** (진단 ①)
- v3 설계에 있던 「자동 −15%」가 지금 규칙에 빠져 있다. 자동은 편하되 손으로 하는 게 확실히 이득이어야 선택이 의미를 갖는다. (v3 §7 결정 필요 2번과 같은 항목)

### P1 — 새 규칙이 조금 필요한 것

**P1-1. 돌발 이벤트 선택지에 스탯 체크** (진단 ①, Long Live the Queen)
- 지금 `RandomEventTable` 선택지는 A/B 둘 다 누구나 고를 수 있다. 표에 `condStat/condMin`(예: 「주파수 질문」 매력 40)이 이미 있는데, 옛 자동 판정에서만 쓰이고 지금 선택 화면은 무시한다 — 이 값을 A 버튼 잠금에 쓰면 된다. 한쪽에 `매력 40 필요`, `체력 60 필요` 같은 조건을 붙이고, 모자라면 버튼이 회색 + 「매력 8 더」.
- 체크 성공 보상은 크게(하트·돈·숙련). 이벤트 글은 그대로 두고 조건·보상 숫자만 붙인다.

**P1-2. 인물 친밀도와 「알바처 사람들」** (진단 ⑥, 스타듀·우마무스메)
- 알바·놀기 카드에 그 장소에서 만나는 인물 얼굴 아이콘(꼬마·아줌마·가게 사람 등). 같은 인물을 여러 번 만나면 하트가 쌓이고, 하트 2·4·6에서 **4컷짜리 짧은 일상 장면**.
- 코드에 옛 `Affinity.Reward` 가 남아 있어 틀은 재사용 가능.
- **주의(대본 규칙)**: 반전 전에 정체를 흘리는 대사 금지, 사라진 인물에게 산 사람이 반응하지 않기, 엄마 얼굴은 CS7 전까지 안 보임. 일상 장면은 「겪은 일만」 쓰고, 컷씬에 이미 있는 장면(밥 해 주기 등)을 되풀이하지 않는다. → **새 글이 들어가므로 결정 필요.**

**P1-3. 계절 축제 4번** (진단 ②, 프린세스 메이커 수확제 · 스타듀 축제)
- 러닝이 없는 긴 구간(CH2~3, CH5~6, CH8~9, CH16~17)에 달력 행사 하나씩: 유채꽃 사진대회(매력) · 해녀 물질 대회(체력) · 귤 따기(순발력) · 겨울 라디오 사연(감성).
- 형식은 기존 미니게임을 쓰되 **스탯이 점수에 보너스**(예: 매력 10당 +1점). 1·2·3등 보상 → 「키운 게 여기서 이긴다」.
- 격주 미니게임 일부를 축제로 바꾸면 총 횟수는 늘지 않는다.

**P1-4. 달력 화면** (스타듀)
- 52주 한 장에 대회·축제·컷씬·이벤트 자리를 아이콘으로. 이미 시네마 화면에 주차 타임라인 시안이 있으니 그 모양을 재사용.

### P2 — 결정 필요 (이야기·단서·엔딩에 닿음)

**P2-1. 단서를 「육성으로」 얻게** (진단 ①⑥ — 가장 효과가 크다고 봄)
- 지금: 컷씬 뒤 카드에서 버튼으로 확정.
- 제안: 단서마다 **육성에서 해야 할 일**을 하나씩 건다. 예시(이름만, 대본 불변):

| 단서 | 걸 수 있는 육성 조건(예) | 이유 |
|---|---|---|
| 91.9 라디오 | 라디오 교육(`dev_radio`/`les_ham`) 3회 | 라디오를 고칠 줄 알아야 복원 |
| 돌 세 개 | 송전탑 알바(`job_tower_fix`/`job_tower_watch`) 2회 또는 체력 N | 송전탑 아래를 자주 가야 다시 쌓음 |
| 하트 흔적 | 해녀 알바/바다 쉼(`job_haenyeo`/`rest_sea`) 2회 | 부표를 볼 기회 |
| 편지 스무 통 | 배달 알바(`job_delivery`) 2회 | 편지를 만질 기회 |
| 보석 머리띠 | 감성 N 이상 | 물건을 보고 멈춰 설 마음 |
| 이름 | (조건 없음 — 지금처럼) | 엔딩 A/B 기본 분기 유지 |

- 조건을 못 채우면 카드에 「아직 뭔가 모자라」만 뜨고 **다음 컷씬 전까지 채우면 얻을 수 있게**(한 번 놓쳐도 만회 가능).
- 효과: 156번의 누름이 「기억을 되찾는 준비」가 되고, CS7 반전이 **내가 다닌 곳들**로 이어진다. 엔딩 3개와 분기 규칙(`ClueSystem.EndingId`)은 그대로.

**P2-2. 「스무 살 하늘」 에필로그 카드 한 장** (프린세스 메이커)
- 엔딩 시네마는 그대로 두고, 크레딧 뒤에 가장 많이 한 알바·가장 높은 스탯으로 고른 한 컷(「등대 불을 켜는 사람이 됐다」 식). 컬렉션에 모이게 하면 2회차 동기가 된다.
- 반전 구조(하늘이는 이미 죽었다)와 맞는지 **사용자 판단 필요** — 맞지 않으면 「하늘이가 남기고 간 것」(마을에 남은 흔적)으로 바꿀 수 있다.

**P2-3. 2회차 계승** (우마무스메 인자 계승)
- 새 회차에 지난 회차 최고 스탯의 10%와 숙련 ★ 일부를 물려받는다. 이미 얻은 단서는 카드에 「본 적 있음」 표시.

## 5. (삭제) — 사용자 확인: 스토리모드의 주인공은 신이 가슴 아픈 가족 사연을 보고 사람처럼 살게 해 준 **살아 있는 사람**이다. 생활 층(밥·잠·병원)은 이야기와 어긋나지 않는다.

## 6. 추천 순서

1. **P0-1 미리보기 + P0-2 목표 띠** — 화면 글 두 줄로 「고민」과 「방향」이 생긴다. 1회차 작업.
2. **P0-3 숙련 + P0-6 자동 효율** — 선택이 쌓이게. 1회차.
3. **P1-1 스탯 체크 + P1-3 축제** — 키운 게 이기는 순간. 2회차.
4. **P2-1 단서를 육성으로** — 사용자 승인 후. 이야기와 육성이 한 줄로 이어지는 핵심.
5. P1-2 인물 하트, P2-2 에필로그, P2-3 계승은 그 뒤.

## 7. 결정 필요 목록

1. 게이트 — **사용자 결정: 그대로(체력 하나).** 대회별 스탯은 「추천」 표시만.
2. 자동 모드 효율 −15% 적용 여부(P0-6).
3. 단서 획득에 육성 조건을 걸지(P2-1) — 걸면 표의 조건 확정.
4. 인물 일상 장면(P1-2) 추가 여부와, 누가 글을 쓸지(사용자 문체 가이드 적용).
5. 에필로그 카드(P2-2)가 반전 구조와 맞는지.
6. ~~생활 층~~ — 해당 없음(주인공은 사람).
